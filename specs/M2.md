## 5. Known traps

- **Pull at departure vs arrival.** MV-03/HZ-10 use the pull at the departure cell for
  both impulse and warp. Do not re-evaluate mid-move.
- **Flattened distance.** Warp distance ignores Void: it is Chebyshev distance between
  flattened sector coordinates, even across galaxies. A destination that is Void or
  outside `universe_size × galaxy_size` is a rejection, not a failed warp.
- **Counter semantics (D-100).** `consecutive_turns_in_range` increments at TP-03 each
  turn the ship is still in range *after* movement; destruction happens the turn
  `turns_left` reaches 0, so a Sun-like star kills on the 7th turn in the cell, not
  the 8th. Write the test before the code.
- **Drain floors at 0; recharge caps at max.** Both are config; neither is a literal.
- **Game over must drop the save before publishing** `game.over`, so a crash after the
  message cannot leave a resurrectable save (OV-09c).
- **AI captains with no ships** are removed the same turn; the snapshot must not keep
  orphaned ids. Tests count captains == ships' distinct owners.
- **Persistent move + warp in the same turn** for the same ship: warp wins and clears
  `move_remaining` (`[ASSUMED]`, log it).
- **Do not weaken a gate.** If a scenario cannot be constructed from `world_index`
  for a seed (no wormhole, say), the gate tries the next seed from a small fixed list;
  that is gate logic, not game logic — report it if the list runs out.
