## 4. Known traps

- **ZeroMQ slow joiner:** a SUB that connects after the first PUB misses it. That is
  why `state.hello` repeats every 2 s and terminals render it only when its
  `turn_no` is newer than what they last drew. Do not sleep-and-hope.
- **Rich in a new console:** create `Console(force_terminal=True, legacy_windows=False)`
  with `PYTHONUTF8=1`; call `console.clear()` then print once per turn (full redraw,
  GRD-06). Flickering is acceptable in M1; partial repaint is not.
- **prompt_toolkit and the lock:** run the prompt in the main thread; the SUB
  listener in a daemon thread that sets an `Event` on `turn.resolved`; use
  `patch_stdout()` so bus messages can print while the prompt is up.
- **psutil cmdline matching:** match on both `--role <r>` and the repo path (or
  `starbour.exe`), never on `python.exe` alone — the gates and Usman have other Pythons.
- **Determinism:** never iterate a `set` or `dict` whose order feeds the RNG or the
  snapshot; sort by id. Never touch the global `random`. Tuples as JSON keys →
  use `"x,y"` strings as in C3.
- **Atomic save:** write `game.json.tmp` then `os.replace`. A crash mid-write must
  leave the previous save intact.
- **Closing a console window** sends the process `CTRL_CLOSE_EVENT`; you cannot
  rely on `atexit`. The launcher's poll loop and the engine's per-turn autosave are
  what make closing T1 safe (TL, BUS-06) — do not add a save-on-close path that
  would need to run inside the dying window.
- **`CREATE_NEW_CONSOLE` on Windows 11** may open Windows Terminal windows rather
  than conhost, depending on the user's default terminal setting. Both are fine;
  do not try to control which.
- **Port reuse:** set `LINGER 0` and close sockets on exit; the live gate checks
  the ports are free before and after.
- **Do not weaken a gate to pass it.** If smoke/03's "≥ 50 % of AI ships moved"
  cannot be met because sectors are tiny or AI ships sit alone in 1-cell sectors,
  that is a finding about the generation defaults — report it; do not edit
  `verify/`.
